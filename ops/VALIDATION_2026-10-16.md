# 自动更新整改验收

## 结论与范围

2026-10-16 在小主机完成运维模块验证，并按授权将实际应用更新至 main `5c68bce1c8bc896d70c0a3b7a4f3d09e0db1014a`。本批只修改 ops 工具、测试及文档，没有修改 web、Java 后端或 Agent 业务源码。前后端均跟随 main，不冻结旧前端。

原故障链是：源码先快进，构建超过 systemd 时限被终止；后续任务因为 Git 已同步而退出，运行容器仍是旧制品。新流程分别记录源码、已构建镜像和已验证部署，失败不能更新部署标记。

## 小主机验证

- `python3 -m unittest discover -s ops/tests -v`：55 项通过，用时1.401秒。包括构建/发布失败重试、实际镜像与版本不符、缺报告、超时/中断、错误静态资源、首次迁移保护及旧上传文件不可读时禁止替换。
- 正常构建 main 的后端、前端、Agent 镜像，核验不可变镜像 ID 和 OCI 源码标签；前端 HTML 和入口 JS/CSS 实际可用。
- 加密备份在独立 MySQL 中恢复，演练 V25→V31 迁移及应用启动后，再执行实际切换。原菜品 ID 和账号数量保持；MySQL/Redis 容器身份与启动时间未改变。
- 非 root 后端切换前发现旧上传文件属主不兼容，修复属主后验证文件内容摘要未变，原图实际返回图片；将候选 UID 的只读检查加入发布前置条件。
- 实际验证 Agent 源码版本、MCP 无凭据401、匿名身份拒绝、CSRF 获取和会话 Cookie 属性。未调用真实模型，未发送邮件；邮件只验证 TLS 主机名和 SMTP 认证。
- 既有自动更新 timer 和保活 timer 恢复运行。成功重跑更新器返回 `verified-current`，六个应用及数据容器均未重启。独立恢复验证容器已清理；已经停用的 SillyTavern 没有恢复。

## 失败证据与限制

现场先后发生 GitHub 连接超时和公网只读请求超时。失败时更新器非零退出，保留已部署清单，没有重启业务容器；最后 Git 拉取及公网首页、目录回查成功。不能据此认定网络已经永久恢复。原始失败记录与成功记录同时保留在维护者私有工作区，凭据、用户内容和完整运行配置不进入仓库。

公网 HTML 会被 Cloudflare 插入附加脚本，因此源站核验 HTML 摘要，公网核验入口资源及其内容与源站一致。不能用公网整页 HTML 摘要不同直接判定部署失败。

主分支身份安全迁移会使旧会话失效，无法证明归属的历史菜品保留未核验状态；不能通过同名用户名自动认领。首次切换和新增数据库迁移仍需人工演练，工具不会自动回滚数据库。旧镜像元数据不完整，现场单独保全旧 JAR 和静态文件，不能宣称完整旧镜像可直接恢复。

本记录证明发布工具与本次切换，不代表整项目功能、真实手机性能或所有网络故障均已验收。
