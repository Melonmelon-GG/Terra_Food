# 地图与运行配置修复验收

## 结论

2026-10-20，已修复地图主源配置在发布时丢失的问题，同时核查Agent、邮件、数据库、Redis、上传、反向代理和会话配置。现有Vue源码、样式、页面结构和交互代码没有修改；没有数据库迁移。

地图采用显式构建配置、配置参与镜像身份、最终制品能力校验；运行配置采用明确的私有输入、完整生效配置HMAC及容器逐字段核验。新增配置回归CI，避免只看进程存活和本站HTTP200就宣布外部功能可用。

## 发现与处理

| 发现 | 处理与证据 |
|---|---|
| Git源码导出不包含未跟踪的地图配置，Docker构建也没有传入Key | 恢复有效浏览器Key，以独立公开配置经BuildKit secret传入；不将后端环境文件复制到前端 |
| 当前制品天地图代码被编译移除，只剩OSM，备用连接又失败 | 验证天地图底图、中文标注和地址解析真实请求；恢复主源，保留原备用与重试逻辑 |
| 同源码SHA改变配置可能继续复用错误镜像 | Web镜像同时绑定完整公开配置摘要，制品描述声明能力与关键JS摘要；部署后核验真实响应内容 |
| Agent模型Key、地址和模型名只存在旧展开Compose/容器中，运行环境文件缺失 | 保留原值迁入明确的私有环境文件，发布覆盖显式引用；新增受鉴权保护的 `/ready` 核验实际进程加载值 |
| MCP残留不需要的旧Agent令牌 | 清理多余凭据，限制各角色可接收的服务/模型凭据，发布前发现越界即拒绝 |
| 只比较源码不能识别邮件等运行设置变化 | 私有HMAC纳入四个应用服务的环境、挂载、命令和安全设置；变更触发应用并再次核验 |
| 未合并修复可能被夜间main覆盖 | `required_ancestor` 在上游包含修复前阻止回退，合并后继续自动更新 |

静态摸查记录62处环境配置消费点，区分浏览器构建、服务端运行和禁用组件；该数是声明位置数，不是62个独立功能或已证明所有配置路径。

## 验证

全部构建和测试在小主机完成，无截图。

- 运维回归71项通过；包括缺配置、私有字段进入前端、同源码配置轮换、模型参数缺失、邮件/挂载变化、错误制品、凭据角色、超时与失败重试，以及浏览器新增Vite输入必须更新契约的检查。
- Agent回归10项通过；配置就绪鉴权、空Key拒绝、配置身份变化、取消和并发预算。没有调用真实生成模型。
- 隔离浏览器3项通过：移动端主底图/中文标注和地址解析、主源失败后备用源、全部失败后手动重试。外部服务由确定性替身提供，只证明控制流。
- 实际部署公网浏览器390与1366宽度回查均通过：真实天地图底图和标注解码成功，地图错误未显示，未触发OSM回退；无脚本异常。拦截非读请求，不执行生产业务写入。
- 应用数据库凭据可认证，未发现全局ALL PRIVILEGES或全局转授权；Redis认证PING通过；上传目录对服务UID可读写，现有文件可读；SMTP主机名/TLS与认证通过，未发邮件。这些不是完整数据库授权审计或邮件送达证明。
- 公网制品描述与关键JS摘要匹配；四个应用容器配置一致，数据库与Redis容器未重启；临时验证容器已清理。更新器复查没有重启服务。

首轮浏览器执行器存在嵌套只读挂载及脚本路径错误，修正执行器后定向复跑。原始失败记录与后续成功记录均保留，没有降低业务断言。

## Agent模型核验

当前供应商认证探测中，匿名GET /models返回401，携带配置Key返回200，说明该Key被这个受保护接口接受。未做推理，不证明完整聊天、工具调用、额度或延迟均正常。

配置模型 `deepseek-v4-flash` 未出现在实时清单，但[DeepSeek官方兼容说明](https://api-docs.deepseek.com/guides/search_fetch)明确仍接受该别名，并路由到当前Flash服务；因此保留既有模型选择，不将其误判为无效配置或擅自换模型。对公开模型清单，工具不会仅凭200就宣称认证成功。
