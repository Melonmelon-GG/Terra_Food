# 定位与收录阻塞修复（2026-09-25）

## 确认情况

无法取得反馈者的机型、浏览器和错误提示，不能认定其设备具体为什么定位失败。但在从线上 terrafood-web 复制出的原始前端静态文件上，使用隔离浏览器、阻断地图瓦片并模拟用户身份，复现了同一条产品阻塞：地图加载遮罩覆盖整个地图，不能点击；未选坐标时收录按钮只提示先选点，表单无法打开。操作未向生产发送写请求。

线上HTTPS响应正常，未观察到禁止geolocation的响应头。浏览器定位仍受设备、权限、定位服务及网络影响，见[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。合成测试不能证明某台真实手机的定位服务已经恢复。

## 根因与修改

1. 地图瓦片就绪被当作交互前提。加载提示改为局部、鼠标事件穿透，保留可点击重试；地图选点不再被整个遮罩阻挡。
2. 表单入口错误依赖地图选点。已登录用户现在可直接进入收录表单，选择当前位置、返回地图或手动输入经纬度；空值、非数值和越界坐标仍禁止提交，不填默认坐标。
3. 自动定位只依赖浏览器回调。统一为12秒总等待上限，浏览器请求10秒并允许较快的低精度结果，仍提示核对实际美食位置；取消、手动编辑、离开页面后忽略迟到结果。不会用IP位置冒充用户位置。
4. 反查地址依赖多家第三方服务。限制整体等待8秒；失败保留坐标、显示人工补全提示。打开表单、重置地图和离开页面会取消反查并推进请求代次，防止旧响应回填。
5. 地址与坐标随父组件异步变化可能覆盖输入。表单打开时保存位置快照；本账号草稿可以恢复手填位置，明确的新地图选点优先。输入省市、地址或坐标会停止当前定位，提交前也停止定位。
6. 无定位时从全国地图寻找不便。提供已有城市导航，城市中心只移动地图，绝不自动作为美食坐标，必须选点或明确填写。

中英文提示同步；保留原有图片上传、审核流程和API字段。未更改后端、数据库迁移、用户权限或地图数据供应商。

## 验证

全部构建与浏览器运行在小主机独立前端预览容器，端口仅回环。现有后端和数据库没有用于造测试数据。

- `npm run build` 类型检查和构建通过。
- 线上旧静态制品的阻塞复现通过：`location-evidence/live-baseline.json`。
- 专项7组通过：城市导航不自动选点、手填位置草稿、迟到地址、权限拒绝后手填并提交、定位成功/迟到回调隔离、无回调12秒超时、同步异常/无效定位值、瓦片故障下390/1366宽度选点（部分场景包含同组多子项）。见 `location-evidence/hotfix-regression.json`。
- API与定位使用确定性替身，验证提交请求字段，不声称实际数据库新增已完成；后端原有DTO允许可选地区/地址、要求有效经纬度，接口契约未改变。
- 最初测试脚本等待手机布局中本就隐藏的缩放按钮，导致测试前置失败；修正为等待地图控件挂载后完成对照，未修改预期以放过业务故障。
