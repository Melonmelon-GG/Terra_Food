# 请求与组件生命周期整改

本次从 main `740c0f1` 实施，修复多个组件重复读取、身份复核连带重载和异步卸载清理。页面结构、样式、文案和用户入口保持原样；没有部署或修改生产数据。

## 行为变化与责任划分

- 菜品详情由详情页统一读取，公开详情与评论跟随菜品 ID；点赞、收藏和想吃状态跟随身份与认证代次。相同账号的身份对象更新不再清空详情、评论和输入。
- AI 只使用详情页已经验证的上下文，不再独立 GET 菜品；上下文具有页面所有者，离页清理不会误清新页面的数据。身份复核期间隐藏 AI，保留同账号的输入；真实换账号或角色变化仍销毁旧组件，迟到回复不会回填。
- `/auth/me` 的前台安全复核继续保留，同批事件合并。网络失败按既有 30 秒预算退避；成就通知成功结果复用 30 秒、失败短退避，同账号复核不再每次加载通知。
- 目录键包含页码，地图键包含筛选、视口和缩放。相同在途查询合并；当前成功结果分别最多复用 60/30 秒。翻目录页不重读相同地图查询，手动重复搜索、重试和收录成功仍可以明确刷新。
- 公共读取使用有界共享模块：音乐清单 5 分钟、地区 60 秒、标签 30 秒。标签键包含会话代次与用户 ID；换账号/退出主动清理，创建/审核/合并标签主动失效。地区解析、收录和导入成功失效地区缓存。
- 每个消费者独立取消，共享请求只在最后一个消费者取消时中止；返回副本防止组件修改数组污染其他组件。失败不缓存，不自动重试写请求；缓存满时不取消其他组件仍需要的请求。
- 详情、状态、标签与清单补齐取消和卸载保护。音乐点击监听器在挂载时同步注册并对称移除，避免迟到清单响应为已卸载组件注册事件。
- 不支持 structuredClone 的移动 WebView 使用 JSON DTO 复制回退；复制失败会明确拒绝 Promise，不让界面永久等待。

## 详情与足迹接口兼容

原详情读取会登记足迹，不能将重复 GET 简单删掉后漏掉延迟恢复身份的访问。本次配套拆分：

| 接口 | 行为 |
|---|---|
| `GET /api/foods/{id}` | 默认保持旧客户端登记访问并返回更新后热度的行为；先核验详情可访问，再登记 |
| `GET /api/foods/{id}?recordVisit=false` | 新前端读取公开内容，不登记访问 |
| `POST /api/foods/{id}/visits` | 已认证角色及 CSRF 保护；先核验可访问，再登记，返回 `{ "heat": N }` |

新页面在身份确认后，为该页面的用户与菜品组合发起一次登记。使用已有每日唯一访问规则，不重复增加当日热度；登记不阻塞内容。返回热度只在页面和身份仍匹配时更新。失败不自动循环重发，下次进入页面可以重新登记。

没有数据库迁移，没有修改每日访问规则。POST 的客户端取消不能撤销已经开始的服务端事务。

## 复跑

使用 Node 22、项目锁定的 npm 依赖和已安装 Chromium，在隔离预览与可写证据目录中执行：

```sh
npm run build
node --experimental-strip-types --test scripts/shared-read.test.mjs
REQUEST_URL=http://127.0.0.1:18528 REQUEST_OUTPUT=/evidence node scripts/request-lifecycle-smoke.cjs
```

脚本只接受回环地址并拦截 API。`REQUEST_CASES=music-unmount-listeners` 可定向复跑，未匹配/零场景非零退出。`REQUEST_BASELINE=1` 采集 main 的三个共同序列。`request-visual-compare.cjs` 在 `/evidence/browser-baseline` 和 `/evidence/browser-fixed` 比较布局和 PNG；Chromium 路径在脚本内，与本轮既有运行镜像一致。

后端执行 `mvn -B test`；定向执行 `mvn -B -Dtest=FoodVisitControllerTests test`。以上命令继续在小主机使用独立目录，不指向当前部署。
