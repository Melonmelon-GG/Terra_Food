# 业务数据整改与验证说明（2026-09-22）

## 兼容变化

- 新增 `GET /api/foods/mine/page?page=1&pageSize=20`，最大 50，响应 `{items,total,page,pageSize}`。旧本人菜品与想吃列表限定前 50 条，新界面应使用分页；这两个旧数组接口不再承担导出全部数据用途。
- 打卡幂等成功记录在删除后保留 24 小时墓碑。同键、同内容重放已删除记录返回 **410**；同一天新的实际体验使用新键。账号删除仍级联清除此账号的幂等记录。
- 菜品标签关系先核验菜品公开/作者/管理员权限。匿名及他人访问待审菜品统一 404；管理员可读取待审标签。
- 旧标签 ID 沿合并链解析规范标签；合并迁移全部别名，记录每条迁移关联是否此前已在目标存在。治理操作取得全局标签治理锁，再以当前读验证标签。该锁只覆盖低频修改；普通公开读取不取得此锁。
- 地图成员接口保留原视口参数，并同时约束服务端解析的网格 ID。聚合与成员使用同一 FLOOR 网格表达式；经度 180 归入最后一个格子。
- 私人查询和写入重新核验不可复用主体。本人菜品仅包含 `ownership_status=VERIFIED` 的记录；历史不确定归属由独立预检和人工证据流程处理，不按同名猜测。

## 公共查询与缓存

旧 FoodService / DiscoveryCountService 的无版本 `@Cacheable` 已移除，设置 `CACHE_TYPE=redis` 不会重新启用这些旧键。详情始终查当前可见性。

新增 `public_discovery_version`：创建、编辑、审核、删除、导入及标签修改登记事务提交前版本递增；版本与业务写入一起提交/回滚，取得版本行锁在业务锁之后。公开查询在计算前后读取已提交版本；版本变化时重试一次，仍变化则 409。

新发现缓存与 Spring Session Redis 分离，使用进程内有界缓存：最多 256 项、30 秒 TTL，仅接纳无关键词的前三页目录和全国默认点位。计数缓存同样有界，任意关键词与视口不进入缓存。默认 `app.discovery-cache.enabled=false`，验证后可显式启用；保持关闭时并发预算仍生效。进程重启清空缓存不影响数据。

公共发现入口最多 32 个在途请求、8 个回源执行者；同键共享请求最多等待 2 秒，独立回源最多等待 200ms，预算超限返回 429。提交后的旧缓存清理异常只记类别，不把成功写入伪报为失败。缓存日志不含完整查询键。

想吃列表最多处理当前 50 条，关联菜品一次批量查可见 ID；无词元不查候选。自由文本每项至多 200 个轻量候选（不拉故事和地址正文），固定保留 Top-3。小匹配缓存 256 项/5 分钟，绑定用户 ID、条目 ID、内容与持久公共版本；它不与公开发现缓存混用。建议结果不是穷举最优匹配。

## 验证入口

所有命令仅在小主机隔离环境执行。本文件记录验证方法，不是通过证据。

普通单测包含 `FoodCheckinRetryTests`、`FoodTagVisibilityTests`、`DiscoveryCacheTests`。`support/TestActors` 仅为直接调用服务的单元测试构造主体/事务标记，不证明真实事务行为。

`SecurityBusinessMysqlTests` 使用完整 Spring 应用、实际 Flyway schema、独立 MySQL 连接和真正事务代理。必须同时满足：

- `RUN_AUDIT_BUSINESS_MYSQL_TESTS=true`
- `DB_URL` 的数据库名以 `terra_audit_` 开头；测试启动前条件检查，启动后再次检查数据库名与 `REPEATABLE-READ`。
- 设置该隔离库与 Redis 的连接环境变量，不能使用现有部署的连接配置。

运行 `mvn -Dtest=SecurityBusinessMysqlTests test`。它启动随机端口应用；为资源统计避免同时启动另一份被测后端。数据库 fixture 仅准备前提，验收动作经真正 Spring Service 事务执行。用例：并发同键、删除墓碑、标签/印记最后一格配额、待审标签权限、连续合并别名和旧 ID、聚合视口成员与删除后公共版本、精确网格边界及跨日界线范围。HTTP/Redis Session 浏览器场景由综合验收补充。

另有 `LegacyOwnershipUpgradeMysqlTests`，仅在 `MIGRATION_DB_URL` 指向 `terra_audit_` 前缀的全新空库时运行。先迁移至 V21，构造 A 删除后 B 复用用户名的真实历史，再升级到最新；使用实际 Mapper 验证 B 不能列出或编辑 A 的菜品，公开作者不错误链接到 B，旧合并别名可修复。测试从不 DROP/清空已使用库；保留结果供查证。

该套件生成唯一前缀 fixture，保留在本次可拆卸数据库内供查证；结束由隔离 Compose 项目删除测试卷，不会全库 reset。

## 维护与回滚

V26 将打卡幂等结果外键改为 `ON DELETE SET NULL`，新增标签治理锁和关系审计。V29 新增公共数据版本。均为增量迁移，不修改 V23 等已应用文件。

过期打卡幂等记录可人工分批执行 `ops/sql/expire-checkin-idempotency.sql`，每次最多 1000 条；24 小时内墓碑不得提前清理。脚本不安装定时任务。

紧急降级先关闭新发现缓存；保留幂等墓碑、主体核验和历史归属隔离。不能回退到删除墓碑/按用户名鉴权的版本。新表与审计不做破坏性逆迁移。

剩余边界：内存预算/性能目标、真实 HTTP 并发、迁移与断连失败由本轮小主机证据决定；本说明不声称这些已通过。标签关系审计支持明确范围的人工修正，但不提供忽略后续修改的一键撤回合并。
