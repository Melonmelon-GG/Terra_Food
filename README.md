### 不止前台，还有一起维护图鉴的人

管理员与子管理员可以通过后台维护社区内容：

| 审核与维护 | 批量收录 | 分工协作 |
| --- | --- | --- |
| 审批菜品，处理昵称、签名与蚀刻章等展示内容 | 导入 `.xlsx` / `.xls`，识别不规则表头与地区信息 | 主管理员授予或撤销子管理员角色 |
| 查看内容概览，维护菜品与用户状态 | 返回重复、跳过与问题行提示，方便核查 | 子管理员参与日常内容管理 |

<details>
<summary><strong>关于功能边界、审核和账号的小提示</strong></summary>

- 游客可浏览地图、菜品与公开食客档案；收录、评论、点赞和个人主页需要登录。注册包含人机验证与邮箱验证，并支持邮箱验证码重置密码。
- 普通用户提交的新菜品与后续修改需要审核；管理员、子管理员提交的菜品可直接通过。
- 封面可选，支持 JPG、PNG、WebP，默认上限为 5 MB。文本草稿可保留，刷新后图片文件需要重新选择。
- 登录用户当天首次访问一道菜时增加热度，同日重复访问不重复增加。浏览足迹表示“看过”，不是线下到访或吃过的证明。
- 当前成就包含首次登录奖励，尚不是完整的等级或活动任务体系；蚀刻章支持保存、编辑、删除与选择展示。
- AI 推荐仅供参考；评论先生成草稿，由用户点击确认后发布。用户身份由 Java 登录会话确定，浏览器不持有模型密钥。
- AI 功能依赖额外服务与模型配置；不启用 Agent 也可以使用基础网站。可尝试问：“推荐几道成都的菜”“根据我最近看的菜推荐一下”。
- 自动定位需要授权，失败后可手动选点；音乐可能需要点击页面或播放按钮后才能播放。

</details>

## 一起续写 · 联合开发者启动指南

前面是网站能带来的体验，下面是把它跑起来的方法。**按自己的工作范围选择一条路线即可，无需一开始就启动全部服务。**

### 先选适合你的方案

| 方案 | 适合谁 | 本机需要运行什么 |
| --- | --- | --- |
| A：基础网站开发 | 修改菜品、地图、账号或管理后台 | MySQL + Redis + Java 后端 + Vue 前端 |
| B：前端单独联调 | 只改页面，团队已有开发后端 | Vue 前端，代理到约定的开发后端 |
| C：完整 AI 联调 | 修改“余”、工具调用或对话记忆 | 方案 A，再启动 Agent 与向量存储相关容器 |

**注意：当前 Compose 不包含 Java 后端和 Vue 前端。** 即使执行 `docker compose --profile agent up`，这两个应用仍需单独启动；它不是一条命令完成网站生产部署的方案。

以下终端命令以 **Windows PowerShell** 为例。macOS / Linux 可使用相同的 Git、Docker、Maven、npm 命令，将 `Copy-Item` 换成 `cp`、`$env:NAME = "value"` 换成 `export NAME="value"`，并按步骤进入对应目录。尖括号里的值必须替换，不能原样运行。

<details>
<summary><strong>方案 A · 基础网站开发｜MySQL + Redis + Java + Vue</strong></summary>

### A. 基础网站开发

准备 JDK 21、Maven 3.9、Node.js 22（与 CI 一致）及 Docker Compose v2。若已有本地 MySQL / Redis，可跳过容器启动，直接配置数据库连接。

**1. 获取代码与配置本地依赖**

```powershell
git clone https://github.com/Melonmelon-GG/Terra_Food.git
cd Terra_Food
Copy-Item .env.agent.example .env
```

已有 `.env` 时不要覆盖。编辑根目录 `.env`，首先将 `MYSQL_ROOT_PASSWORD` 改为自己的本地开发密码。

基础方案不调用模型，但 Compose 中部分 Agent 变量使用必填插值，解析配置时也可能检查它们。因此请保留模板里的非空字段；只有方案 C 才需要把 Agent、MinIO 和模型配置换成真实可用的值。不要把模板占位值用于实际部署。

```powershell
docker compose up -d mysql redis
docker compose ps
```

等待 MySQL 和 Redis 就绪。Compose 会创建 `dayan_food` 数据库；后端首次启动时由 Flyway 创建表并写入初始地区与示例菜品。

如果使用已有 MySQL，请自行创建数据库，并确保 Redis 正在运行：

```sql
CREATE DATABASE dayan_food
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
```

**2. 启动 Java 后端（新终端，从仓库根目录开始）**

```powershell
$env:DB_USERNAME = "root"
$env:DB_PASSWORD = "<与根目录 .env 中 MYSQL_ROOT_PASSWORD 相同的值>"
$env:REDIS_HOST = "localhost"
$env:REDIS_PORT = "6379"
$env:SESSION_COOKIE_SECURE = "false"

# 首次本地体验可初始化管理员，无需先完成邮箱注册。
$env:INITIAL_ADMIN_ENABLED = "true"
$env:INITIAL_ADMIN_PASSWORD = "<自行设置的强管理员密码>"

cd dayanfood-backend
mvn spring-boot:run
```

后端默认地址为 `http://localhost:8080`。在网站登录页选择管理员身份，用户名为 `admin`，密码为上面设置的值。已有同名账号不会重复创建或被此配置重置密码。

首次创建成功后，在下次启动前将 `INITIAL_ADMIN_ENABLED` 改为 `false`，并移除 `INITIAL_ADMIN_PASSWORD`。初始化管理员适合本地进入后台；验证普通用户注册和审核流程仍需普通用户账号。

> 根目录 `.env` 由 Compose 读取，**不会自动成为 `mvn spring-boot:run` 的环境变量**。Java 需要的变量应在启动它的同一终端或 IDE 运行配置中设置；新开终端需要重新配置。

**3. 启动 Vue 前端（另一个终端，从仓库根目录开始）**

```powershell
cd web
npm ci
npm run dev
```

访问 `http://localhost:5173`（若端口被占用，以 Vite 输出为准）。默认通过 Vite 将 `/api` 和 `/uploads` 代理到 `http://localhost:8080`，开发时优先保留这个同源代理方式。

可选地图配置：在 `web/.env.local` 中填写 `VITE_TIANDITU_KEY=你的天地图浏览器端Key`，保存后重启 Vite。不配置时有 OpenStreetMap 等回退路径，但底图和地址识别仍依赖外部网络。不要将服务端密钥放进任何 `VITE_*` 变量。

**4. 需要测试注册 / 找回密码时，补齐邮件配置**

在启动 Java 的同一终端或 IDE 中设置以下变量，再重启后端：

```powershell
$env:MAIL_HOST = "<SMTP服务器>"
$env:MAIL_PORT = "587"
$env:MAIL_USERNAME = "<SMTP用户名>"
$env:MAIL_PASSWORD = "<SMTP密码或授权码>"
$env:MAIL_FROM = "<发件邮箱>"
$env:MAIL_SMTP_AUTH = "true"
$env:MAIL_STARTTLS_ENABLED = "true"
$env:MAIL_SSL_ENABLED = "false"
```

以上是 STARTTLS / 587 的配置形式，端口和加密方式应与邮件服务匹配。没有邮件服务时不要把注册验证码发送失败误判为网站整体无法运行，也不要为联调关闭验证码校验。

</details>

<details>
<summary><strong>方案 B · 仅做前端｜连接团队开发后端</strong></summary>

### B. 仅启动前端，连接团队开发后端

适合后端同学已经提供独立联调环境的情况，本机不需要再启动 MySQL、Redis 或 Java。

在 `web/.env.local` 中设置：

```dotenv
# 替换为团队约定、从你的电脑可访问的开发后端地址。
VITE_BACKEND_TARGET=http://127.0.0.1:8080
```

然后在 `web` 目录执行 `npm ci` 和 `npm run dev`。该配置同时代理 API 与上传图片；修改后需要重启 Vite。

请使用**专用开发环境与测试账号**，不要默认连接生产后端进行上传、审核或删除测试。登录异常时共同检查开发后端的 Cookie、CORS 和代理配置；本地 HTTP 与生产 HTTPS 不应共用同一套 Cookie 安全设置。

</details>

<details>
<summary><strong>方案 C · 完整 AI 联调｜在基础网站上启用“余”</strong></summary>

### C. 启动完整 AI 联调环境

先完成方案 A。通过 Docker 运行 Agent 时，本机不必额外安装 Python；直接开发或验证 Python 代码时使用 Python 3.12，与容器和 CI 保持一致。

**1. 编辑根目录 `.env`，填入真实配置**

| 变量 | 说明 |
| --- | --- |
| `MYSQL_ROOT_PASSWORD` | 保持与现有本地 MySQL 密码一致，不要随意更改 |
| `AGENT_INTERNAL_TOKEN` | 自行生成的强随机内部令牌，建议至少 32 个字符；Java 与 Agent 必须一致 |
| `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | 本地向量存储依赖的访问凭据，替换模板占位值 |
| `OPENAI_API_KEY` | 你选择的 OpenAI 兼容模型服务密钥 |
| `OPENAI_BASE_URL` | 与密钥对应的接口地址；使用非默认供应商时需要按供应商填写 |
| `AGENT_MODEL` | 该接口实际支持的模型 ID，不要默认模板值适用于所有供应商 |
| `EMBEDDING_MODEL` | 默认 `BAAI/bge-small-zh-v1.5`；首次使用可能下载模型文件 |
| `AGENT_PERSONA` | 可选；留空使用内置“余”人物卡，填写则覆盖默认人格 |

**2. 从仓库根目录启动相关容器**

```powershell
docker compose --profile agent up -d --build
docker compose --profile agent ps
```

此方案在 MySQL / Redis 之外启动 Agent API、MCP、Milvus、etcd 和 MinIO。首次拉取镜像、构建 Python 依赖与下载嵌入模型可能需要较长时间；容器显示运行中也不等于所有依赖已经可用。

**3. 为 Java 配置 Agent 连接并重启**

保留方案 A 中数据库等环境变量，另外设置：

```powershell
$env:AGENT_INTERNAL_TOKEN = "<与根目录 .env 完全相同的内部令牌>"
$env:AGENT_SERVICE_URL = "http://127.0.0.1:8090"
```

然后重新运行 Java 后端。前端正常启动并登录后，可打开“与余交谈”入口测试。

MCP 默认通过 `http://host.docker.internal:8080` 回访宿主机 Java 后端。若后端不在这里，通过根目录 `.env` 的 `BACKEND_INTERNAL_URL` 覆盖，再更新对应容器。

```powershell
# 从仓库根目录检查日志；分享日志前先检查并隐藏敏感信息。
docker compose --profile agent logs --tail=100 agent-api agent-mcp milvus
Invoke-RestMethod http://127.0.0.1:8090/health
```

`/health` 仅用于确认 Agent API 响应，不能证明模型密钥、MCP 工具和向量记忆全部可用；还需在网站实际完成一次对话。修改 Agent 源码后需重新执行带 `--build` 的启动命令，当前 Compose 没有配置源码热更新挂载。

</details>

<details>
<summary><strong>启动遇到问题？展开配置与排查清单</strong></summary>

### 常用配置与排查

完整后端配置见 [application.yml](dayanfood-backend/src/main/resources/application.yml)，Agent 说明见 [agent-service/README.md](agent-service/README.md)。

| 情况 | 优先检查 |
| --- | --- |
| Java 连不上数据库 | MySQL 是否就绪；`DB_PASSWORD` 是否正确；非默认连接使用 `DB_URL`、`DB_USERNAME` |
| 登录或验证码异常 | Redis 是否可达；如需认证，配置 `REDIS_PASSWORD`；邮件是否配置完整 |
| 登录后仍显示未登录 | 是否通过 Vite 代理访问；本地 HTTP 下是否误设 `SESSION_COOKIE_SECURE=true` |
| 端口冲突 | 默认使用 3306、6379、8080、5173，完整 AI 方案另使用宿主机 8090；调整映射后同步修改连接配置 |
| 菜品提交后未出现在地图 | 普通用户内容需要审核，先到个人主页查看状态 |
| 图片无法显示 | `/uploads` 代理是否生效，后端 `UPLOAD_DIRECTORY` 是否可读且文件仍在 |
| 地图空白或地址识别失败 | 外部地图服务网络、天地图 Key；自动定位需要浏览器授权与安全上下文（HTTPS 或 localhost） |
| “余”暂时无法连接 | Java 与 Agent 令牌是否一致；模型地址、模型 ID、密钥与容器日志 |
| Compose 提示缺少变量 | 根目录 `.env` 是否存在，必填字段是否非空；不要提交真实配置 |
| 更改 `.env` 密码后 MySQL 认证失败 | 初始化变量不会自动修改已有数据卷中的数据库密码；核对原密码，不要直接删除数据卷 |

停止本地依赖可在仓库根目录运行 `docker compose --profile agent stop`，保留容器与数据。不要把 `docker compose down -v` 当作日常重启方式，它会移除命名数据卷。

当前 Compose 面向本地开发，MySQL / Redis 端口映射未限制为回环地址；不要直接照搬到公网机器。正式部署应单独规划 HTTPS、反向代理、数据库网络隔离、受限账号、密钥管理，以及数据库和上传文件备份。生产 `prod` 配置默认启用 Secure Cookie。

### 提交前的检查与协作约定

在各自目录执行：

```powershell
# 仓库根目录 → Java 后端
cd dayanfood-backend
mvn --batch-mode --no-transfer-progress verify

# Java 后端目录 → Vue 前端
cd ../web
npm ci
npm run build
```

修改 Agent 时，在已安装 `agent-service/requirements.txt` 的 Python 3.12 虚拟环境中，从仓库根目录运行：

```powershell
python -m compileall -q agent-service/app
cd agent-service
python -c "import app.main; import app.mcp_server"
```

修改 Compose 时，从仓库根目录运行 `docker compose --profile agent config --quiet`（需要完整的非空环境变量）。

当前 [CI 工作流](.github/workflows/ci.yml) 在推送到 `main`、以 `main` 为目标提交 PR，以及手动触发时运行。它检查后端测试、前端类型和构建、Python 语法与模块导入、Compose 配置；**不等同于浏览器 E2E、真实数据库集成测试、完整 Agent 对话测试或自动部署**。涉及页面和接口的修改仍需手动验证对应流程。

- 从最新主分支创建工作分支，例如 `feat/food-search`、`fix/map-location`、`docs/readme`，完成后通过 PR 合入。
- PR 说明改动目的、验证方式；页面调整附上桌面与移动端截图，配置调整说明新增变量。
- 数据库结构通过新的 Flyway 迁移变更，不改写已在共享环境执行的迁移文件。
- 前端新增界面文案同步维护中英文语言文件。
- README 更新时同步维护 `README.md`（中文）与 `README.en.md`（英文），保持功能、配置和启动命令一致。
- 不提交 `.env`、`.env.local`、模型密钥、邮箱授权码、数据库密码或真实用户数据。
